# Native companion design

The companion follows the visual language of [web UI PR #30](https://github.com/cdemeke/SugarClock/pull/30), pinned for asset provenance to commit `bf477f9cc6fcb7f6627c673cefd7ad4fbde458ad`. Four original PNGs are copied byte-for-byte into native image sets: `configuration-icon.png`, `dashboard-icon.png`, `diagnostics-icon.png`, and `logo.png` (named ConfigurationIcon, DashboardIcon, DiagnosticsIcon and BrandLogo). The existing full-resolution App Store icon is retained. No web page, firmware asset bundle or unrelated PR #30 changes are merged by this design update.

`DesignSystem.swift` defines shared adaptive colors, cards, field surfaces, action buttons, status badges, page headings and navigation rows. Light mode uses the reference's `#f3f7f4` background, white cards and `#16894a` accent. Dark mode uses `#0f1117`, `#1e2128` and `#39d97a`. System appearance selects the theme. Illustrated section icons, subtle borders/shadows and rounded cards carry the branding into native SwiftUI. On iPhone, navigation stacks and vertically arranged cards replace the web sidebar; wider layouts cap the content width for readability.

My Clocks is the launch page. A single saved clock starts connecting there; multiple clocks wait for selection. The device page groups firmware-supported services by their confirmed enable switches: Enabled services and More services. Unknown values remain in a neutral Services section, and unsupported services are omitted once the schema loads. Grouping uses the last loaded clock settings, not unsaved edits, and remains visible during reconnection. Blood Sugar, Time, Pixel Pets, Alerts, Weather, Pomodoro, Stopwatch, Countdown and Notifications have dedicated service pages. System Monitor lives under Clock settings because it requires an external system-data integration. Display, Wi-Fi and Clock settings follow in a utility card.

Each service has a header enable switch and hides its options while disabled without discarding saved preferences. Blood Sugar Off also disables alerts when saved. Weather explains its location/API-key requirement; Pomodoro and Stopwatch describe physical clock controls; Notifications and System Monitor explain their integration requirement. Countdown uses a native date/time picker, storing the existing epoch-seconds value and identifying the phone's display time zone. Labels, choices and category membership are native; field availability, limits and saved values come from firmware. All pages use the existing explicit-save/readback flow.

Pixel Pets uses selectable Fish and Ghost preview cards rendered locally with SwiftUI Canvas at the firmware's 10 FPS. The sample awake animation follows the firmware's tail flicks, bubble drift, ghost shimmer and short waving bursts. It contains no live readings, weather effects or glucose-status overlays. Both animations respect Reduce Motion with calm static poses and suspend their timeline when the page disappears or the app is inactive. The preview cards have no Pause/Play controls or explanatory footer. A checkmark and border identify the draft choice; only the existing explicit save/confirmation flow changes the clock. VoiceOver names each pet and marks selection.

Foreground connection recovery makes at most five attempts, then offers Retry. Permanent errors and cancellation still stop earlier. Only connection/read operations are retried; settings writes are never automatically replayed.

Connection status and the green circular spinner share a row. Reconnection says Reconnecting; a stopped failure uses an exclamation icon and Retry, without the saved-settings reassurance. Indeterminate operation, Wi-Fi scan and save-verification indicators use the same green spinner outside disabled save buttons. Wi-Fi trials and signed OTA retain the existing transport and operations.

`SettingsDraft.swift` keeps editing state separate from rendering. It emits only explicitly changed fields, preserves configured-secret indicators without retrieving secrets, treats keep/replace/clear distinctly, and keeps original integer mg/dL thresholds intact during viewing or unit-only changes. A failed save leaves the draft available to correct or retry; a confirmed saved/readback result resets it. Field bounds and string byte limits use firmware metadata. Secrets are discarded on leaving the page.

Current validation (iOS build 14): all 62 Swift tests, the complete simulator build with assets and the signed Release archive pass. New tests distinguish unsupported/unknown/disabled services, preserve legacy glucose presentation and verify that enabling a service does not clear saved options or prematurely change confirmed grouping. Labeled simulator fixtures visually cover the service dashboard, green reconnecting spinner, failure message, Weather, Pomodoro, Countdown, save checking and accessibility-size initial loading. Fixtures disable Bluetooth and interaction; these checks do not replace physical end-to-end service/save or VoiceOver testing. The fifth-attempt recovery and five-attempt exhaustion are covered by session tests. The Swift pixel renderer was compared with the production firmware drawing functions for 720 frames and the static pose per pet (1,442 exact buffer comparisons). Firmware 0.3.2 already exposes the settings used by these pages.

See the [screenshot gallery](../docs/screenshots/README.md), [build instructions](README.md) and [review correction validation](../docs/PR29_REVIEW_CORRECTIONS.md). Original PR #30 assets are bundled through Assets.xcassets. Existing unassigned AppIcon warnings remain.


### Wi-Fi selection and help

Opening Wi-Fi does not start a scan. Choose another network opens a dismissible sheet and starts one search; Search again explicitly repeats it. The list uses only results from that sheet’s completed search, omits the connected SSID, and returns the chosen network to the existing credentials and connection-trial form. Closing the sheet cancels its scan task. Manual entry remains available on the Wi-Fi page.

Notifications explains that other apps or automations supply the message text, that this app does not compose messages or mirror phone notifications, and that glucose warnings are configured separately under Alerts. Its controls identify the default display duration and sound for urgent messages. My Clocks says Choose a clock. Help opens with a short SugarClock description and a link to https://sugarclock.com.
