# Physical acceptance — device smoke test completed; full acceptance pending

The initial implementation did not flash a clock. A subsequent user-authorized USB smoke test flashed a configured TC001; see BLE_DEVICE_SMOKE_TEST.md for the measured results and TLS-memory correction. No real ESP32/iPhone pairing session has yet been verified by the agent. Host/simulator-SDK compilation and mocks do not establish BLE security, power-loss resilience or reliability. Record date, TC001 hardware, firmware hash/version, iPhone model/iOS version, test steps and observed results for each check. Do not export passwords, provider URLs, bond keys, passkeys or raw flash backups as diagnostics.

- [ ] Stock/new USB install: unconfigured clock advertises a distinct name, fresh six-digit code fits the display, initial window expires after two minutes, first setup works through the clock's radio.
- [ ] Verify with actual ESP32 + iPhone that pairing negotiates **authenticated LE Secure Connections**, 128-bit encryption and bonding; confirm no Just Works/legacy downgrade. Wrong code/canceled prompt cannot read settings, write settings, access status, or receive private values. Test with an unbonded BLE client outside admission.
- [ ] Button regression: middle short/double taps retain brightness/address actions; release after 1–3s snoozes, 3–10s opens pairing, and 10s resets only bonds. Pairing never snoozes alerts. Check the gesture while the address screen is open and verify the outer-button power shortcut is no longer used.
- [ ] Configured clock: no new-phone admission without middle-button hold-and-release gesture; existing glucose display/alerts continue. Admission expiry, repeated attempts and rate-limited/bounded connection timeouts recover.
- [ ] Signed OTA upgrade from a configured prior release: no Wi-Fi/glucose/password/display/alert loss; physical pairing loads current values without credential re-entry.
- [ ] Legacy single-slot USB migration: verify recovery backup, NVS preservation, CA bytes, unknown files, old overlay quarantine, reboot and original enterprise association. Interrupt bootstrap only on a recoverable lab device with an approved recovery plan.
- [ ] Two clocks in range: choose and pair each, assign nicknames, reconnect to the matching authenticated full identity, including suffix-collision handling by passkey confirmation.
- [ ] App termination, foreground/background transitions, phone reboot, clock reboot, out-of-range and Bluetooth-off/denied states; at least 50 repeated sessions. A timed-out write displays unconfirmed outcome and does not automatically replay it on another session.
- [ ] Minimum/default MTU 23 and larger negotiated MTU, long URL/token configuration, dropped/repeated fragments, out-of-order/oversize/invalid JSON, and disconnect while writing/reading a multi-frame message. No stale response is mistaken for a saved acknowledgment.
- [ ] Wi-Fi trial: correct PSK, open network, hidden SSID, wrong password, nonexistent SSID, missing DHCP, 5 GHz-only network, enterprise PEAP/TTLS, preserved CA/identities, and certificate-required failure. No implicit enterprise downgrade.
- [ ] Failed Wi-Fi trial reconnects to previous saved network; unavailable previous network remains saved and retries/portal recovery continue. No glucose credentials cleared, including Improv provisioning after firmware upgrade.
- [ ] Distinguish network/DHCP, persisted configuration, internet DNS, provider reachability, provider authentication and actual fresh glucose retrieval. Test bad Dexcom credentials and expired URL/token independently of Wi-Fi success.
- [ ] Phone replacement, four-bond capacity, stale iOS/clock bonds, and ten-second physical reset. Verify app settings and certificate remain byte-for-byte equivalent after Bluetooth reset. Verify old phones cannot reconnect after bond reset.
- [ ] Concurrent web/BLE/fleet/button edits preserve omitted fields and serialize persistence. Invalid combined thresholds fail atomically. Replace/clear/unchanged secrets behave distinctly. Viewing mmol thresholds and navigating back never changes their integer mg/dL values.
- [ ] Interrupt NVS save before journal, during legacy mirrors, and after mirrors before cleanup on a lab clock. Bluetooth firmware recovers the complete journal. Do not claim old firmware can recover an interrupted new journal; test documented downgrade procedure.
- [ ] Normal glucose HTTPS polling during BLE discovery/pairing/configuration does not block display/button/alert processing. Urgent glucose, urgent notification and active buzzer preempt passkey rendering. Include failed provider requests/timeouts and live weather-enabled configuration.
- [ ] Manual and scheduled signed OTA: low battery, urgent readings/buzzer, active timers, low heap, setup AP and unavailable time defer correctly. BLE stops to free memory and resumes after check/failure/deferral. No permanent auto-update blockage.
- [ ] OTA success, signature/hash/network failure, planned reboot, failed startup validation/rollback, and app reconnection. Verify actual current version and startup validation before declaring success; verify prior version/rollback errors remain visible.
- [ ] Measure actual free heap, minimum free heap, largest free block and loop latency during idle, scan, pairing, 4 KiB request, glucose HTTPS authentication/fetch, failed retries, and OTA. Capture `[DIAG]`/`[MEM]` and authenticated status snapshots; minimum free heap is global since boot, so reboot between scenarios when measuring scenario minima. Compare the largest block before/during/after pressure. Record maximum task stack usage if available.
- [ ] Repeat at least 50 full settings sessions plus HTTPS and signed OTA attempts on **4 MB/no PSRAM** hardware; inspect allocation failures, watchdog resets, falling heap floors and fragmentation. Never infer free heap from ELF static RAM size.
- [ ] iPhone Dynamic Type through accessibility sizes, VoiceOver navigation/labels and error announcements, dark/light mode, portrait/landscape, keyboard access to long secrets and numeric threshold editors.
- [ ] Signed development install and eventual TestFlight archive validation with the owner's real Apple team, entitlements, privacy disclosures and icon. No placeholder signing credentials.

Distribution gate: all security, preservation, alert-continuity and OTA/rollback checks above must be completed on actual hardware before calling this firmware/app release-qualified. This checklist grants no permission to flash, publish or upload.
